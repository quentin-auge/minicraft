# ARCHITECTURE.md

Agent guide to the MiniCraft static rewrite: what lives where, how data is
stored, how it flows, and how each system works. Read this before changing code.

## Tree

- `index.html` — static shell: menu (no backdrop veil, solid `#1c2030` panel like help), help float (centered hold-to-show, controls + portal diagrams), spawn float (`#mobmenu`, centered hold-to-show, clickable rows, no Ok/Cancel), hotbar DOM (incl. master's unlock-pop keyframes), Ender Dragon boss bar, mega-ignition flash/veil overlays, portal-travel spiral overlay, rocket prompt + countdown overlays, Three.js import map. Cursor rule, same on all three menus: hand (`pointer`) on the central panel and its buttons/rows, default arrow on the backdrop.
- `main.js` — bootstrap (`?test=1` loads the test instrumentation hook, inert unless set): scene, input wiring, main loop, world startup. Owns the pause gate (`simActive`: locked + started + built + no menu open via the `menus.js` registry): every sim/visual tick runs only behind it; the loader, the fog reveal, the debug readout, and the final render run while paused. `X` is unbound; `V` (cheat only) cycles the world simulation speed (×1/×2/×4/×8/×16, wrapping) through `sdt`, while player/camera/chain/loader keep real `dt`; mega burns Firestorm Wall, ultra burns tornado + fat shock rings + wall + trimmed Titan smoke, countdown lights run one strobe swell (no style bindings); mega overlays decay on sim-time; dense mega FX, sliced carve jobs, and DPR dip run behind the gate (`fxDip` latches DPR 1 synchronously in `onExplode` — or early via `megaImminent()`, now also for lit ultras — so the blast frame itself renders cheap). Point-blank mega (camera inside the pool union range) fires full overlays + a camera-centered lens burst + 5° FOV kick and nothing else (no furnace tail). Shake is one impulse plus decay everywhere (no sustain): same ~1 s duration for 1/2/3/4+, ground/fly, mega/ultra. Outside the crater, overlays need voxel line of sight (`hasBlastLoS`) or they stay off — shake still goes through rock. Ultras reuse the same LoS overlay path with the inferno overlay (plus a close-range lens burst + FOV kick), and the normal band-wipe destruction. `buildWorld` slices voxel gen across frames (`generateOverworldAsync`, 12 rows/slice, token-aborted), builds the spawn neighborhood (radius 2), then the loop enters the game on the first rendered world frame (`pendingPlay`: the Play click only arms entry plus a best-effort lock) while the fog reveal (`tickReveal`, per-frame, loader-exempt) expands underneath and far chunks stream in; dense-pool warmup (scene-add + compile + reset, no hidden render) runs post-unlock, plus a burst warmup (one seed particle per countdown variant, flash geometry, debris pool) so the first rocket tick never pays a program link mid-countdown. Ticks portals (fill refresh + cross-dimension travel handoff to `runTravel`) and notifies the portal index of blast edits. Travel loads its destination behind the spiral in two phases (`runTravel`: sliced scene teardown under the fade-in (`beginDispose`/`disposeSome`, ~80 chunks/slice, queue cleared last so no half-torn key ever drains), then destination voxels with no mesher calls, then a full-ring budgeted mesh drain capped ~1.5 s in short slices with an extra yield after heavy ones + fill refresh + shader compile once per dimension per session (`compileAsync`: synchronous link + async poll, skipped once the set linked — GL programs persist in the context)); the spiral paints before any heavy work, the canvas freezes behind the opaque overlay, and at lift the fog snaps straight to its final range with the reveal marked done — ready to go, no arrival hitch, no reveal, no visible streaming (cap fallback, e.g. deep Nether: the missing-chunk guard hides unbuilt distance without holes). Cross-dim switches regenerate the End and the TNT cube, retain the overworld and the Nether, resolve the arrival through the portal last left in the destination (visibility-first placement, else the dimension spawn), reset meshes/fills/lights/fuses, and keep fly mode on. A dragon kill increments the TNT tier progression, rescans portal fills, and rebuilds the bar in place so newly unlocked tiers reveal immediately; New World resets kills (see `tntunlock.js`). Owns the rocket wiring: `initRocket`/`tickRocket` behind the sim gate (pilots pin, plain walk/fly/hook/grapple/F/Z inputs defer), ENTER hold-to-launch outside fly mode (fly stays on in the cabin), edit routing (voxel-normal parked, hull model in flight, blocked only mid countdown/landing), `carryRiders` after the farm tick. The C key drives the cheat target debug (`targets-debug.js`): the keydown/keyup handlers and the per-frame tick are wired here, and a world rebuild or a dimension travel drops the target. Mega-pool mob ejection rides the injected `onMegaPool` hook (centroid + R, same arc as the player through `core/launch.js`): every live same-dim farm mob inside R launches, carried/riding mobs and the dragon excepted, and same-dim Endermen caught in the member-sphere union teleport out at the same detonation. Other blasts report through the injected `onCrater` hook as blast descriptors (normal spheres per batch; ultras their wiped range at wipe end) — `blastPredicates` teleports only what the blast could have touched: outside the blast, or on the surface that remains.
- `src/ui/hotbar.js` — dynamic item list (add/remove/change/reset ops, selection tracked by id), rendered bar. `resetItems(to)` swaps the whole list (slot icons memoized per block id, so re-bars skip the re-encode); the active dimension's `dimHotbar` picks it (overworld base set, TNT tiers only, End substitutes Moon Water and Glowstone for water and flower, locked mega/ultra filtered), so travel and fresh builds re-bar and selection follows by id. `resetItems(to, popId)` pops only that one item with master's `unlock-pop`/`slotPop` (gold border, scale, glow), dropping the class on `animationend`; dimension travel, New World, and every other bar change rebuild silently.
- `src/core/blocks.js` — block ids, BLOCK_INFO (solid/opaque/placeable, plus `light` emitter key for emissive blocks), liquid/TNT predicates; rocket family (`HULL`/`HULL_ACCENT`/`THRUSTER`/`PAD`, worldgen-only solids, windows reuse stock `GLASS`).
- `src/core/noise.js` — deterministic hash2/valueNoise/fbm.
- `src/core/store.js` — monotonic `worldRevision` invalidates geometry caches on writes, resets and dimension switches; voxel storage, one Map per dimension keyed by `DIMENSION_KEYS` (`over`/`tnt`/`end` live, `nether` reserved), sparse column tops, and per-dimension protected-cell sets used by Endstone and the generated return frame. Key packing covers ±65535 on every axis; `registerInfiniteDim` lifts the ±96 cube (and the y = 0 floor) per dimension — the TNT sky roams free, bounded dims keep the exact old bounds. `unprotectCell` releases vehicle hull and portal cells back to normal writes. Pad + hull cells stay protected at every phase (parked in the store, in flight via `dockedCells`); every blast/edit/carve path clears indexes only after the voxel write succeeds, so a surviving protected cell never loses its variant. `ensureChunkArea` materializes the 3x3 lazy-source square around a chunk build (returns the freshly generated keys); `rimRefreshKeys` selects only built neighbours adjacent to those for refresh. Only the Nether registers a lazy source, so every other dimension hits the early-return no-op.
- `src/core/launch.js` — shared mega-launch ballistics, three-free: `PLAYER_GRAVITY` (37.44, the single gravity behind every blast arc) plus `computeMegaLaunch` (body-center launch off a pool centroid capped at R: `Vup = 22 + 8f`, `airT = 2*Vup/G`, uniform 1.5R travel, horizontal speed clamped 4..40, null past R). Both the player knockback (`fx/tnt.js`) and the mob flight (`mobs/mover.js`) dispatch through it, so the two trajectories cannot drift. Headless-tested by `tests/headless/mobs/blast.test.mjs` (launcher shape, free-flight 1.5R range).
- `src/core/liquid.js` — floating-liquid anchor rule (three-free): `LIQUID_FACE_NB` (6 faces) + `LIQUID_EDGE_NB` (12 edges) share one `LIQUID_ALL_NB` 18-neighborhood for seeds, flood connectivity, and anchor test (corners join and anchor nothing); faces-first `touchesSolid`, pure `findFloatingLiquids` discovery (one fused 18-read per cell, groups ground on any solid contact with an early break, `kept`-bridge + rescue pass so a break never orphans a branch, `PURGE_GUARD` 60000, `y = 0` exempt); `edit.js` wraps it with the voxel writes + portal notifies, blasts reuse it through `onLiquidPurge`. Headless-tested by `tests/headless/edit/liquid-purge.test.mjs` (faces, edges, corners, diagonal chains, edge seeds, lava).
- `src/core/airpocket.js` — three-free static air-pocket test: an air cell counts as trapped when its air flood (sideways + down only, never +y, 1024-cell cap, per-chunk-build cache) exhausts inside non-air (solid or any liquid). Wells open to the sky trap, open surface and detached-cube surroundings never do, mixed liquid + solid cavities trap; one rule for all liquids, decided at mesh build with no per-frame work.
- `src/core/cheat.js` — cheat flag (`?cheat=1`, session-fixed): bypasses the TNT tier locks and enables the Z dimension cycle (over → end → nether → tnt). Unlocks the target debug too (the C key: aim a block, hold C to grow the selection into the box between that block and the cursor, release to arm it, C on a mob sends it there).
- `src/core/textures.js` — procedural canvas textures, including the master Endstone palette, per-block materials, liquid two-role surface materials (outside color 0.9 fronts — overworld water 0.95; open-air backs share the outside sheet plus an `insideRole` opacity/transparent/fog override — the diver's window; trapped-air backs read the inside color 0.8 — water/lava light blue, moon water `#b0b4b9`), per-variant glowstone textures/materials plus fogged distance-faded pad-corner ghost variants, moon rock lit+emissive material (pale base grey 160, emissive 0.9), rocket hull/accent/thruster/pad textures. Runtime eye-medium fog overrides (`setLiquidFogOverride` — moon water and lava while submerged) flip cached and region-cloned liquid materials in place with a recompile; new builds follow the live state.
- `src/render/halobake.js` — baked-halo registry (`HALO_SOURCES`): every source tints the opaque blocks around its positions at chunk-build time (mesher `setColorAt`, white = untouched), permanently and level-wide, so all sources read lit instead of a max of the nearest ones; sources self-register beside their data (glowstone everywhere, portal frames Nether-only in family colors), new families add a spec and nothing else changes. Per-spec suspension (`setHaloSuspended`, tracked per chunk as `suspendedBuilt` in `mesher.js`): still-hold bridge strokes suspend the glowstone halo and freeze pool-light resyncs, and the touched union plus chunks built under suspension re-queue through the budgeted drain on bridge release for the tint pass.
- `src/render/poollights.js` — selective dynamic pool: one lamp per glowstone cluster fitting in a 5×5×5 cube (groups connected past a Chebyshev gap of GAP = 3, transitively, so dotted lines read as one group; a lone stone is a cluster of one; the lamp floats at the centroid, colored by the centroid-nearest stone), plus one lamp per grid-plane crossing on sprawling chains (invisible planes every GRID blocks on x, y and z; lamps spaced at least GRID apart within a chain so a chain lying in a plane lights every GRID blocks); spots carry block keys so lamps never migrate on camera motion or unrelated edits; eligibility has hysteresis (enter at DIST, leave past 1.2×DIST) except pad-corner ghosts, which burn in their base red/yellow with a hard cap at the fog far and no hysteresis (see `poolspots.js`); nearest-first fill to SPOT_BUDGET (16) — past 16 spots only the nearest burn; every validated Nether portal and every sited tunnel ring burns one centered lamp with no cap (`portalFrameLights` + `netherRingLights`); ring cells are excluded from clusters via `isNetherRingCell`; snap only, no glide; halo stays the base layer everywhere.
- `src/render/poolspots.js` — three-free spot selection for the dynamic pool (split out of `poollights.js` so the headless harness covers it): union-find grouping, 5×5×5 cluster lamps at the centroid plus GRID-spaced chain crossings, DIST enter / 1.2×DIST leave hysteresis with nearest-first fill to SPOT_BUDGET; pad-corner ghosts resolve through `padGhostBaseVariant` and die at min(DIST, `GHOST_POOL_FAR`) with no hysteresis.
- `src/render/chainproxy.js` — optimistic overlay for chain edits: transient per-id `InstancedMesh` in the blocks' own shared materials (cubes + per-variant glowstone + per-id liquid cubes reusing the outside-sheet material at the same render order; flowers alone stay on the normal path), fed by `proxyNote` each tick and culled by chunk rebuild versions (`mesher.js chunkVersion`) with an 8 s sim-time TTL backstop; cleared on world build and dimension travel.
- `src/render/waterfog.js` — eye-in-liquid fog/background murk while submerged (moon-water murk runs far so the submerged eye reads down the shaft; lava murk runs dense and dark — near 1.5 / far 35, mix 0.88 toward indigo-black — so the submerged eye reads thick ink instead of landmarks; only read while the eye sits in lava, so overworld water/air paths are untouched). Exported `LIQUID_FOG` keeps the per-liquid tuning in one place.
- `src/fx/ambient.js` — ambient-effect registry (`AMBIENT`, keyed by a dimension spec's `ambient`): lazy init/tick/exit per dimension switch, never leftover particles.
- `src/fx/nether.js` — Nether ambience: lava-sea embers, volcano eruption fountains, camera-local blue motes while the eye is submerged in lava (dense slow suspension: 1600 strong-blue points for the thick-ink read; renderOrder 12 so they draw over the surface sheet, depth-tested so rock still occludes). Fountain spawns are gated on live crater lava at the spawn cell, so eruptions die with a blasted volcano instead of firing from air (sea embers self-gate the same way on the lava surface).
- `src/world/nether.js` — three-free, stream-first Nether generator: great lava sea with big rugged fbm islands (master's terrain recipe, capped for fan cooperation), winding lava rivers, two hollow fully-closed corner volcanoes with a central lava column on a flat summit, constant-section falls draping over island relief into the sea, 10 stratified high fan tunnels per volcano to the column plus three ground bridge pipes per volcano (tips 5..15 blocks clear of the flank, each landing on its own shelf islet or right on flat island relief), glowstone portal rings sized on the carved mouth with rock collar, doorstep and trimmed approaches, flat lava face at each bore's inner end (`squareInnerFace`: tunnel-frame plane — lava wall behind over a dry rock sill, open walkway + rock sill/lintel ahead, flat on cardinal headings and regular crenellation on diagonals, shaft columns skipped so the mouth follows the natural rock relief inside the lava cylinder; merged-chamber cells deferred to the owning tube), protected return platform; lava-ban mask for O(1) siting vetoes; `setupNether` (one keyed entry per pass via `netherSetupStages`, shared by the sync reference and the sliced paths; the tunnel-siting entry slices within its attempt sweeps through an async twin — the draw RNG is pure-hash, so yields change no trial, verified bit-identical headless) + `generateNetherChunk` via `registerChunkSource("nether")`, `prepareNetherDimensionAsync` boot path (yields between setup stages and platform chunks, so a first visit never holds one long block).
- `src/render/sky.js` — high-altitude sky (per-dimension base colour from the active `DIMENSIONS` env — day blue overworld, pale dusty-rose TNT (red TNT reads dark against it at every distance) — fading to black past the clouds with stars only where the env keeps space (overworld; TNT sets `space: false`); the `SKY_DOMES` registry builds each env `dome` lazily and follows the camera (the Nether's dusk gradient, stars and orange sun disc)); rewrites the murk's air baseline. Reveal regions fade separately (regions.js).
- `src/render/regions.js` — reveal-region registry (`REGIONS`, moon first): each spec declares dimension, membership (`blocks` + `contains`), a camera-driven `factor` 0..1, and an optional `onFade` material hook; `regionOf` classifies a cell, `applyRegions` pushes factors each frame. The moon rock crossfades sky-colour→texture while staying opaque; the opaque moonwater outside sheet mirrors the rock off a dark-grey tint floor (never pure black at distance), the inside/pocket sheets keep their generic opacity with the same tint. Generic gating for any far body/structure — non-celestial volumes included.
- `src/render/orders.js` — transparent-pass compositing ladder (`ORDERS`, the single source of truth for `renderOrder`): `LIQUID_OUTSIDE` 10, `LIQUID_INSIDE` 11, `MOTE` 12, `GLASS` 13, `VEHICLE` 14, `VEHICLE_GLASS` 15, `VEHICLE_FX` 16. three.js renders the opaque pass first, then sorts transparent objects by `renderOrder`; a transparent surface that writes depth erases every transparent fragment drawn after it, so the ladder is ordered by dependency — liquids first (the world's see-through content), then motes riding their surface, then glass (composites over water from either side), then vehicle parts. The moving rocket hull rides the vehicle bands (blocks at `VEHICLE`, its glass one band higher so hull blocks never tint it, the thruster FX at `VEHICLE_FX`) and keeps the source `depthWrite` (solid hull blocks write depth, glass stays depthless — a window, not an occluder), so the water under the flying hull stays visible through it. Consume the constants; raw numeric `renderOrder` assignments are a regression (the hull once defaulted to band 0 and erased every liquid behind it).
- `src/world/overworld.js` — height field, rivers, terrain fill, generation orchestrator (`generateOverworld` sync for tests/headless; `generateOverworldAsync` identical voxels in 12-row slices with `requestAnimationFrame` yields and token abort). Terrain columns bottom out at the dimension's floor level (`floorY`, threaded from the spec).
- `src/world/dimensions.js` — first-class dimension registry (`DIMENSIONS`: generator, env preset, spawn, `arrival` portal-return policy, `hotbar` bar list, `persistence` retain/regenerate, respawn policy, floor level (`floorY`: `0`, `null` = floorless), `exitsGate`/`exitsGateMsg` portal lock (End: while the dragon lives no portal ferries the player out — `portals.js` dispatches through it), `infinite` voxel streaming + `respawnY` floor (`null` = none — the TNT sky has none), `tntTiersUnlocked` (the TNT sky ignores the dragon-kill tier locks)). Overworld and Nether retain voxels; End and TNT regenerate every entry (reusing the pinned `?seed=` session seed when present, fresh roll otherwise). `persistence` alone drives the portal-entry wipe of all per-dimension side state — voxels, glowstone variants/index, flower looks, reaction runs/variants, placed-TNT index, and that dim's mobs (`farm.js handleFarmTravel`): retain keeps everything across trips, regenerate rebuilds everything fresh, so future dimensions inherit the rule with no travel-code fork. Every registered dimension key is a valid `?startdim=<key>` boot target, plus the `moon` and `pen` aliases: overworld boot with the lunar spawn (`findMoonSpawn`) or the pen overwatch (`findPenOverwatch`: hovering above the pen in fly mode, looking straight down), later respawns using the ground spawn. Each spec's `arrival` drives portal returns (`portal` resolves the window last left there, facing it in the Overworld and putting the player's back to it everywhere else; `spawn` uses findSpawn, as in the portal-less TNT sky). `dimHotbar` filters locked mega/ultra per dimension and `dimTntTiersUnlocked` exposes the exemption; `?cheat=1` forces both tiers everywhere.
- `src/world/end.js` — End platform generation and boss progression: protected Endstone square (-36…36 on X/Z), protected return portal frame, End spawn, and the cleared flag that gates the return portal fill. Per-entry resets never touch the cumulative TNT unlock kills (`tntunlock.js`).
- `src/world/tntdim.js` — TNT dimension: legacy bounded clouds-only `193x193x192` cube (same XZ as overworld, `y 1-192`, no floor; still the headless reference) plus the clip-free placer (`placeCloudAt`, `CLOUD_R_MAX`) the streaming lattice reuses, one tier per cloud (all `TNT` or all `MEGA_TNT`, never ultra), compact ellipsoid puffs on a two-phase 3D scatter: 8 sparse megas first, then up to 80 regulars filling every safe pocket (regulars only need 3+margin from each other). Core rule (never violated, enforced constructively + asserted): no blast may reach another cloud — pairwise edge gap must exceed the largest applicable blast radius (40 for any mega-involved pair since mega pools cap at 40 and chain normals, 3 for normal–normal) plus a tier-split per-pair margin from the seed hash (flat 1% for mega-involved pairs, 5–20% for normal–normal) (`blastIsolationNeed` + `pairMargin`); spacing uses each cloud's own bounding radius, so clouds sit as close as the rule allows. Single pale dusty-rose sky (`TNT_ENV`, `space: false` — never black, no stars); `findTntSpawn` stands on regular TNT with headroom.
- `src/world/tntunlock.js` — TNT tier progression: mega unlocks at 2 Ender Dragon kills, ultra at 3 (`UNLOCK_KILLS`), counted per world and reset by New World; `?cheat=1` bypasses every lock for the session. Pure state + predicates (`noteDragonKill` returns the tier this kill unlocked, for the hotbar pop; `resetTntUnlocks`, `isLockedTntTier`, `isTntTierUnlocked`); the TNT dimension ignores the locks, and the bar/placement gates dispatch through these.
- `src/world/tntstream.js` — infinite TNT sky: deterministic 3D cell lattice (normals pitch 48, megas pitch 96 with a `MEGA_PROB` per-super-cell roll — the rarity rate, currently 0.6 for ~10 megas per fog sphere typically, 1.0 fills every super-cell, the structural maximum — spawn's own super-cell mega-free; each mega sterilizes ~20 normal cells, so at 1.0 the sky reads mega-dominated at ~1:25 normals:megas, lower rates trade megas for surviving reds) streamed around the player (nearest-missing cells under a velocity-scaled tick budget — demand pi·R²·v/cell³ at the 80 b/s 2x-gravity design fall, floor 4 cells, 5 ms cap, one batched remesh per tick — plus a 3x3 fall shaft to GEN_R + |vy|·3s while diving, mesh-horizon pre-fill in entry slices, evict past 2×fog + 96 and 15 s unseen), pristine regen from the entry seed, player-pinned cells (edits, portal frames, hook anchor) never evict, sky-grapple synth clouds (≤800, `skyGrapple` capability) checked against deterministic neighbours with nearest-mega fallback, spawn hunts neighbour cells for a standable top when its home cell holes, hardcoded point as the final fallback. No safety net: the sky falls forever (the ±65535 key range is the structural floor).
- `src/world/moon.js` — Moon disc + lake shafts (`MOON_MIN_Y`/`MOON_SURFACE_Y`/`MOON_R`/`MOON_THICK`, surface derived upward from the hand-picked bottom) + `findMoonSpawn` (nearest-to-origin solid cap outside lake shafts, facing the origin) + gone-flag (`isMoonGone`/`markMoonDirty`, lazy + cached over `worlds.over` with an early exit, `resetMoon` dirties); `MOON_MIN_Y` doubles as the Moon reveal region's volume bound. Surface (cap + lakes) builds with the world (tops final before spawn); the hollow underside fills lazily after the reveal in row slices (`generateMoonUnderRows`, idempotent, never seals lake water so shafts stay open below), then the lake join (`joinMoonLakeWater`: shoreline moon-rock teeth fully ringed by water peel to full water columns first, then exact per-cell floods over dense box snapshots fill the trapped air they enclose — sealed notches with moon water, hollow-linked pits with moon rock — so lakes read as contiguous pure water, the underside never ponds stray water, and no moon-water face keeps a pocket back; open verdicts propagate forward so each open region pays one flood) runs once the shell exists (lazy-fill tail, sync full fill) before built disc chunks remesh via `refreshBlocks`; below the moon band the fill finishes synchronously. All Moon voxel writes run only in `dim === "over"` — the lazy fill and the safety net abort on travel elsewhere and the fill resumes on return, so the TNT cube never receives moon voxels (its reveal region is dim-gated too).
- `src/world/glowstone.js` — glowstone color-variant registry (`GLOW_VARIANTS`, 7 entries), per-dimension variant maps + live block index, clustered placement picker (`glowVariantNear`: inherit within 10 blocks, else seeded draw via `setGlowSeed`, ghost entries never seed clusters), plus two reserved pad-corner ghost variants (`PAD_GHOST_RED/YELLOW`, red/yellow look via `padGhostBaseVariant`, `isPadGhostVariant` predicate, `padGhostOpacityAt` distance fade), baked-halo source registration (every normal stone tints its neighbors; ghosts bake black = no halo) plus base-color pool lamps while the fog lets them show (`poolspots.js` fog cap). Variants clear only with the voxel: protected stones (pad corners) keep their color through blasts.
- `src/world/clouds.js` — puff-cluster builder (`generateCloudClusters`: layers/count/salts/puff sizes injected, block chosen per cluster) plus the overworld climbable-deck specialization (`CLOUD_MIN_Y`/`CLOUD_MAX_Y` bounds plus `generateClouds`); spawn and sky reuse the bounds instead of hard-coding altitudes. The TNT dimension reuses the same puff math in compact form (see `tntdim.js`).
- `src/world/trees.js` — tree-type registry (`TREE_TYPES`, oak first), generic growth and ground guards.
- `src/render/flowers.js` — flower-variant registry, baked voxel-cluster geometries (stem/leaves/disc bloom), plus the flight material per variant (`flightFlowerMat`: a transparent clone of the static flower material with its own fade depth, `FLOWER_FLIGHT_FADE`, so a bloom can breathe with a moving hull; the static world keeps the opaque material). Per-block looks live in `world/flowers.js`; this module holds no placement state.
- `src/render/reactions.js` — render side of the block reactions: variant box materials (the look's own texture), one shared translucent shell material per variant (breathing opacity on sim time via `pulseReactionShells`; shells inside a reveal region use region-owned clones breathing the same way, composed with their region fade via `trackShellMaterial`/`syncShellFade` — the generic region fade skips them), and the run visuals (one sinking trigger cube per running reaction synced from `activeRuns()`, drip bursts on arm/settle) behind `initReactionFx`/`tickReactionFx`/`clearReactionFx`. Holds no reaction state.
- `src/world/flowers.js` — per-dimension per-flower look memory (variant + Y angle, three-free): `noteFlowerPlace` draws a fresh seeded weighted-random look at placement (`setFlowerSeed`), the mesher only reads it back, `clearFlowerAt`/ `resetFlowerMemory` drop it on break/blast/new world; `noteFlowerPlaceShared` writes an exact look instead of rolling one (a vessel stamping back its own blooms restores them verbatim).
- `src/world/reactions.js` — block-reaction registry + framework, three-free: `REACTION_TYPES` (base block, accepted triggers, `duration`/`consume`/`absorbsAbove`, `variant`/`refuses`/`onComplete` hooks — a new reacting block, trigger, or outcome is one row) and `VARIANT_LOOKS` (settled appearance data: face texture, shell, sinking-trigger indicator, drip recipe). `armReaction` starts a run on the base cell (eating the trigger unless the cell is busy or a `refuses` hook vetoes — vetoes still eat it and report, for a future fail blink); `tickReactions(dt)` settles runs (reporting absorbed liquid above and spec-touched cells) and releases runs whose base changed; `variantAt` reads the settled mark (self-healing), `clearReactionAt`/`clearReactionsDim`/`resetReactionMemory` drop state on break/blast/travel/new world. Soakable dirt is the first row (any of the three liquids on dirt → 0.5 s soak → wet variant, blue for water/lava, pale for moon water). The framework never writes voxels and never touches the renderer: callers apply, the mesher draws.
- `src/world/village.js` — village layout and structure placement (houses, pen, pool); records worldgen-placed frame-block keys for the portal index (no full-map scan at build); doorstep leveling (`levelHouse`: sill row, 2-cell apron, and interior floor to the village height with 3-high headroom — terrain and vegetation only, neighbours/pen/pool skipped — so every house door walks both ways); corner launch pad (11x11, one cell off a village-square corner, door toward the center) with distance/fog-fading red/yellow ghost-glowstone corners (no halo; pool-lit in the base colors while near) and the parked rocket, via `world/rocketpad.js` (sited last, after every structure).
- `src/world/spawn.js` — overworld spawn selection on finished voxels (`findSpawn`): firm open ground with a frustum-wide clear vista. `findPenOverwatch` is the `?startdim=pen` boot pick: hovering above the village pen in fly mode, looking straight down. Column scans stop at the dimension's floor level. TNT spawn lives in `tntdim.js` (`findTntSpawn`); `physics.js spawnPlayer` dispatches through the active `DIMENSIONS` spec.
- `src/mobs/registry.js` — stable-key `MOB_TYPES` registry with locomotion capability flags (`walk`/`jump`/`float`/`swim`/`fly`: `float` is passive surface buoyancy, `swim` directed underwater locomotion), `grabbable` carry eligibility, homing-TNT targeting flags, create/tick/damage/dispose hooks, optional `release` hook (per-type reset on carry release, after the shared reset), optional `footprint` hook (`{hw, h}` body dims for pre-creation placement), `refuseMsg` (toast on ungrabbable aim), and optional `aimHitTest` dispatch. Flying mobs default to homing-TNT targeting and a three-shot volley cap; specs may override either capability or cap. Live-mob sources (`registerMobSource`/`allMobs`): each mob module registers its set once, so aggregators never hardcode kinds. The projected direction is the plan's `nav.plan` (a unit vector): the corridor servo takes the exit it points at (`updateLane`), and `navPlanAllows` is the plan's veto — a 1-wide lane or a wall ride that runs more than `NAV_PLAN_DOT` off the plan is dropped by the mover, while a rail that agrees with the plan stays (in a corridor, riding the wall IS the path). The commit itself is published by `navCommit` (a `NO_EXPIRY` roam commit), so open roam, wall-follow, 1-wide, and 2-wide do the walking while the planner only chooses where; an entry commit owns the mob meanwhile (the mouth machinery drives it). The plan also owns the band around the planned cells (`NAV_BAND`: the mob's centre stays inside its green cell — a diagonal corner cut alone costs 0.71, a corridor ride 0.5) and the planned-direction veto (`navPlanAllows`); `navPathDistance` (the distance to the planned cells) and `navCellOnPath` (is a cell on the line) are what the mover reads to end a rail that runs against the plan or drifts off the band. The blocked detector measures the ROUTE, not the body: the remaining length along the plan must shrink (`NAV_PROGRESS`), so a mob that slides along a wall — plenty of motion, no progress on the path — reads as blocked (`NAV_BLOCKED_T` 0.3 s) and decides at once: it replans and, if the new route differs, turns to it immediately (the decision is instant, the rotation is not). The replan reads the live mobs as obstacles (`peerObstacles`: a moving mob counts exactly like a parked one, so the route goes around it; with no route around, the plain plan stands and a peer never makes the path vanish). When the replan finds the same route (the same goal and the same remaining length within `NAV_SAME_ROUTE` — a route shifted by a push keeps its shape, a detour around a new wall is longer) and the mob does not move at all (`NAV_STILL_T`), the route cannot be walked and the mob gives up instead of pressing on; the give-up drops the stale commit so the mob decides again in the same tick. Only a world without any path left ends the plan the same way; arrival clears the nav — the mob's centre over a goal cell, or, once it has stopped advancing (`NAV_BLOCKED_T`), its body over the goal block (a corridor end wall leaves a mob's nose nowhere to go, so the last cell is only ever occupied up to the wall); beside the block (tier 1) the same stall reads nose-on-block plus body at the side goal as contact instead (a long nose presses the target a hair outside the arrival square). `navOnPath` answers whether a cell lies on the remaining path: the mouth machinery asks before it draws, so a mouth that does not serve the plan never hijacks the goal.

## Data model

- Block ids are stable integers (`AIR = 0` … `MOON_WATER = 21`); new blocks only append.
- `BLOCK_INFO[id]` carries `solid`, `opaque`, `placeable`, and the `light` emitter key for emissive blocks (glowstone first). Physics and meshing both derive from it; block lights dispatch through it. `opaque` means fully occluding for meshing culls (PORTAL included — its texture is solid, so water sheets and neighbor faces cull against it instead of z-fighting at the contact).
- Voxel key: `(x + 65536) * 2^34 + (y + 65536) * 2^17 + (z + 65536)` (decoded by `keyXYZ`, kept beside the encoder; ±65535 every axis, exact under 2^53); one `Map` per dimension in `worlds`, built from `DIMENSION_KEYS` so new dimensions add storage without a fork. `outOfWorld`/`dimBound` gate raycasts, floods, and clamps per dimension (bounded dims: the old cube + y >= 0).
- No ceiling: columns run any `y >= 0`; `dim`/`world` point at the active dimension's map and tops. The unbreakable floor is per-dimension data (`floorY`: `0` everywhere except the floorless TNT sky (`null`) — no catcher, falling below `-20` respawns in the active dim). Worldgen bottoms out at it: overworld columns, Nether terrain and volcano cores, and the one-block End platform (which is the floor).
- Noise (`noise.js`) matches master's formulas exactly, including its z-flipped
  bilinear blend — required for a sane land/water ratio, do not "fix".
- Sparse column tops (`Map`, missing reads 0; `topAt` reader) track the highest non-air block per column for meshing and spawn; `colOcc[dim]` (`colIdx` → `Set` of occupied y) lets meshing iterate blocks instead of scanning height, and `colLiqTop[dim]` (`colIdx` → highest liquid y) answers swim queries in O(1) — all maintained by `setBlock`, plus the bulk `fillColumn` fast path used only by initial terrain fill (identical voxels and indexes, one bookkeeping pass per run).
- Village state is a single `village` object: center, bounds, houses, pen, pool, radius/houseCount tunables.
- Player state is module-level: `pos`/`vel` vectors, `yaw`/`pitch`, `onGround`,
  step-up/step-down flags, jump buffer/rebound trackers, shared `keys` map. `flyOn` is dimension-independent and survives every portal traversal (all portals sever only the hook and zero velocity).
- TNT state: player-placed normal TNT coordinates are indexed per dimension
  for mega-crater edge queries (purged per dimension on regenerate-dimension entry, kept across trips in retain dimensions); lit fuses live in a `lit` map (`"x,y,z"` → fuse),
  chained blasts wait in a `pendingChain` map (`"x,y,z"` → due time); liquid displaced by placed TNT
  waits in a `displaced` map (`"x,y,z"` → liquid id, restored in that cell
  after its blast unless the kind clears liquids, cleared on world build); placed mega blocks are indexed in
  `megaIndex` for instant pool clustering (added on place, removed as blasts
  consume them, cleared on world build and on every dimension switch (fuses do not cross dimensions — `lit` and its sprites are snuffed on every travel, so no fuse ticks foreign voxels); the blast refresh callback and the
  post-blast floating-liquid purge (`onLiquidPurge`) are injected by the caller.
- TNT tier progression lives in `tntunlock.js`: one cumulative dragon-kill counter for the world (reset by New World; the End's own per-entry boss reset never touches it), thresholds `MEGA_TNT` 2 / `ULTRA_TNT` 3, plus a boot-time `?cheat=1` bypass. The bar and placement read it; the TNT dimension ignores it.
- Glowstone color lives in per-dimension variant maps (`"x,y,z"` key → variant index, default green) plus a live block index per dimension (clustering reads the stones, light buckets read the index — no world scans); placed stones inherit the nearest variant within 10 blocks, cleared on break/blast/world build and per dimension on regenerate-dimension entry (retain dimensions keep theirs across trips — no ghost lights in fresh worlds).
- Flower looks live in per-dimension maps (`key(x,y,z)` → variant index + Y angle): every placement (worldgen scatter, player place) draws a fresh weighted-random variant and angle via `noteFlowerPlace`; the mesher only reads them back, so rebuilds never reshuffle a look; cleared on break/blast/world build and per dimension on regenerate-dimension entry.
- Farm mobs may carry `_narrow` encounter context (`key`, ordered cells, peer, shared meeting active/jam clock, crossing flag and side); the existing passing window/offset fields express its sidestep, and carry reset clears both context and passing state. Farm mobs are per-dimension entities (`type` pig/cow, `dim`, feet `pos`, `hw` 0.32 both, `h` 1.02/1.30, corridor state (`lane`, blend, stall guard, commit `{heading, target, span, runT}`, touch follow line (`t`/`wallSpan` budget, `gentle` glue, `noSlide` parallel flag, `pinWallRide` test hook) + cooldown/turn-hold, entry scan throttle (`entryScanT`) + entry-commit flag, threading state (live 2-wide `passage` kind/axis/key/held, mouth-gated) with tint flags (`tunnelPass` purple approach, `inPassage` orange while threading a 2-wide (live crossing, or any wall ride inside the geometry), `wallFollow` blue, `oneWide` red), `jrng` junction stream), cooperation state (`_peerIdx` tick index, `_plan` one-tick group override + `_planHold` latch + `_rebase` parallel-adopt flag, one-shot `_wantDetach` wall-to-roam switch + `_wantAbort` commit-giveUp flag, `_detour` stuck maneuver, peer-grind state (`_peerStall` leaky contact clock, `_grindPeer`/`_grindEp`/`_grindCool` episode memory, `_peerHold` quiet hold + `_holdTurn` turn guard, `_turnAway` maneuver span)), seeded pen layout via `setFarmSeed`): 4 pigs + 4 cows spawn strictly inside the pen (never fence ring, trough water, or rim); retain dims keep theirs across portal trips (hidden while away), regenerate dims wipe that dim's mobs on entry — all driven by the destination spec's `persistence`, never a dimension fork.
- Render state: `chunkMeshes` (`"cx_cz"` → per-id InstancedMesh), a build queue,
  shared materials cache. Scene, camera, and renderer are owned by `main.js`.

## Data flow (generation)

`generateOverworld(seed)` runs one pipeline: seed → river paths → village layout
→ per-column terrain fill (flattened to stone inside village bounds, water below
`WATER_LEVEL`) → trees/flowers (flowers only on grass with air above, presence
hash-gated by `TERRAIN.flowerDensity`, each placed flower drawing a fresh seeded variant + angle via `noteFlowerPlace`) → `placeVillage` structures. `generateClouds` scatters solid puff
clusters in the `CLOUD_MIN_Y`…`CLOUD_MAX_Y` band afterwards, then `generateMoonSurface` lays the rock cap
with hashed `MOON_WATER` lake shafts at `MOON_SURFACE_Y` (tops final before spawn). Spawn selection (`findSpawn`) closes the pipeline:
nearest firm open ground to the origin whose vista stays clear 50 blocks ahead
across the whole FOV swath and 12 rows above the eye — no wall, trunk, hillside,
or canopy anywhere in the frame. Pen cells excluded, liquids never qualify,
cloud decks and moon rock never qualify for footing (the scan starts below the moon band, so it stays fast).
The legacy TNT pipeline (bounded cube, still the headless reference) is separate: two-phase greedy scatter (`pickCenters` → `scatterTier`: megas placed sparsely first, then regulars accepted wherever their edge gap to every accepted cloud clears that pair's blast need plus its tier-split margin (flat 1% mega-involved, 5–20% normal–normal), using per-cloud bounding radii) → one-tier compact puff clouds (`TNT`/`MEGA_TNT`) → post-fill voxel sweep that throws on any core-rule violation → `tntdim.js findTntSpawn`; regenerates from a fresh seed on every entry (retained dims skip this). The hollow underside shell fills after the reveal, not in the pipeline: `main.js` slices `generateMoonUnderRows` across idle frames (same geometry/salts as the eager port), then remeshes built disc chunks via `refreshBlocks` (`moonChunkCenters`; chunks streaming in later already contain the voxels). Below the moon band the fill finishes synchronously instead, so descending never meets an unbuilt shell.

The Nether is stream-generated: `setupNether(seed)` (rivers → corner volcanoes → cascade bands + ban mask → return platform → bridges sited on landing shelves or natural island relief → high fans) runs once, then `generateNetherChunk(cx, cz)` materializes one render chunk per mesher read: fbm seabed plus lava sea/soul shores, rugged fbm islands with lava rivers and cliff streaks, a 5x5-neighbour cone shell (`SHELL_DEPTH` 3, hollow and fully closed) plus the central `baseY..rim` lava shaft and its flush crown, constant-section cascades draping down the cone and over island relief into the sea, then each tunnel as a hermetic tube (carved 8-wide walk box → 1-block lining plus a buried-only second layer, glowstone ring sized on the carved mouth in one deterministic hue per mouth → open view corridor), followed by the enforcement pass (re-clear bores/corridors, re-seal shells/collars/doorsteps/faces, re-place rings last); the only openings are the frame doorway and the flat lava face over its dry sill (shared-chamber merges stay open doorways between bores, never holes). `generateNetherDimension` is the full reference and `prepareNetherDimensionAsync` the boot path (setup + return-platform chunks only) so `?startdim=nether` reveals instantly while the fog (`fullView`, no unload-horizon cap) and chunk streaming cover the rest; a direct Nether boot then applies the portal arrival around the return frame instead of leaving the player on the raw spawn pad. The Nether retains its voxels between trips and resets only on New World; streamed glowstone registers into the live index, so built chunks pick up the baked halo.

## Data flow (meshing)

Per chunk: iterate each column's occupancy set (`colOcc`, ascending) and
keep exposed blocks only (any neighbor non-opaque), group by id
non-opaque), group by id into one InstancedMesh each (flowers skip the cube
bucket: per-variant cluster meshes with a stored random Y rotation, glass
transparent). Liquids skip cubes entirely: one merged InstancedMesh per
(liquid id, side) of full-block 1x1 boundary faces exactly on the cell
bounds. Faces against same-liquid or opaque neighbors are culled so adjacent
liquid merges into one volume and solid walls (wells, shores) show their own
faces; every bound emits the coplanar pair — a `FrontSide` quad
(`ORDERS.LIQUID_OUTSIDE`, always the outside color 0.9) plus a `BackSide` quad
(`ORDERS.LIQUID_INSIDE`): outside color for open air (surface, detached cubes),
inside color for trapped air (bubbles, wells, mixed cavities, via
`airpocket.js` at build — one rule for all liquids; moon water reads ash gray
`#a8adb2`, and its lake fringe is joined at gen so no pocket back remains). Each viewpoint sees
exactly one sheet per quad (backface culling); both sheets write depth, so
the nearest interface occludes block undersides and far walls. One
`LIQUID_SURFACE` spec per liquid in `textures.js` (stable keys) supplies
color, opacity, and grain, so retinting never touches paint code and new
liquids register a spec without framework forks. Surfaces stay unlit;
glass draws after the liquids (`ORDERS.GLASS`). Chunks within
`RENDER_DIST` build nearest-first (3D distance to the
eye) under a
per-frame budget; edits rebuild only touching chunks via `refreshBlocks`. 3D
distances read cached per-chunk tops (dropped on rebuild/dispose) and the
clear-bubble guard scores the queue once, nearest-first. Columns walk
unsorted (instance order is invisible); meshes carry static conservative
spheres (no per-build computation, no per-frame matrix updates). Steady-state region fades skip the
mesh and generic material loops (late-created materials fade at creation,
the bespoke `onFade` still runs). Non-region meshes share one group per
 chunk, fog-culled as a unit past fog far (the Moon ground content);
region meshes stay scene-level under their fade gate. The
first build is near-synchronous only: the spawn neighborhood meshes before
the first frame, then closed-in fog expands to reveal the world while far
chunks keep streaming in under the frame budget — invisible behind the fog,
and the clear-bubble guard builds anything entering visibility
synchronously, so nothing ever pops in. Empty chunks are tracked as built too,
so deferred edits and held bridges can remesh them instead of losing updates.
Eviction waits for both the loose ring and the fogged range: a chunk outside
`RENDER_DIST + UNLOAD_MARGIN` disposes only once its slab also clears fog
far plus margin, and anything still queued inside the clear bubble builds
synchronously before the frame renders.

altitude or pace; the dive-murk baseline tracks the guard. Chunks that still
materialize inside the visible range

## Pause contract

- Paused = pointer unlocked (menu, incl. the unlocked spawn float) or any hold-to-show float open (help pauses while keeping the lock). `main.js` computes one `simActive` (`worldReady && started && !building && isLocked() && !anyMenuOpen()`, where `anyMenuOpen` counts panels + overlay) and every sim or visual tick runs only behind it: player/hook/knockback, `tickTNT`, `tickPortals`, `tickFx`, precip, block lights, hook visuals, streaming fog, sky, regions, dive murk, camera shake, highlight. Hold-to-show floats pause alike: help on H (centered, locked, no mouse) and spawn picker on B (centered, unlocked, free mouse). Pausing freezes the frame; unpausing resumes it — nothing fires, decays, or catches up in between.
- Time-based logic takes `dt` plus sim-time only — never `performance.now`/`Date.now`/`setTimeout`/`setInterval` in a tick path. Pending futures are state + `dt` countdowns decremented in their tick: TNT chains (`pendingChain.due` off `simNow`), precip sway (sim-time passed in by `main.js`). Portal travel is loader-driven behind the spiral (`runTravel` rAF slices + minimum spiral time), never a sim-time pending, so pausing mid-transition never stalls the load.
- World speed (`V`, cheat only, ×1/×2/×4/×8/×16 wrapping) is one `sdt = dt * gameSpeed` handed to world ticks (mobs, TNT, portals, particles, precip, lights, sky/ambient, blast clocks) and added to `simTime`; player movement, camera/shake decay, chain editing, and loader/visual transitions stay on real `dt`.
- Loader and UI-only code are the only wall-clock exemptions, named here so future agents don't "fix" them: chunk/voxel streaming (mesher budget + `tickTntStream` gen/evict + travel preload/finish slices, loading, not sim) + background moon fill (loading, not sim), fog reveal (`tickReveal`, loading, not sim) + chunk/fill fade ticks (`tickChunkFades`/`tickPortalFillFades`, loading, not sim), `tickDebug` FPS readout, hotbar wheel throttle, hotbar unlock pop (CSS, one-shot), toast/spiral DOM fades.
- New features ship pausable or they don't ship: wire every new `tick*`/`update*` behind `simActive`, keep every countdown in sim-time, and extend this section when adding a new exemption or pending-future shape.

## Broad logic (world)

- Height field: base + hills + roughness, plateau bands, sea-level clamp, basin
  seas, river-bed carving. `heightAt` memoizes per column.
- Village: flat-ish site search, pen/pool/houses placed with mutual avoidance.
- Trees: `TREE_TYPES` registry (oak: trunk 4–35 from `hash2(seed+999)`, round
  canopy). Shared properties live in `TREE_DEFAULTS`; entries override only
  what differs, and the trunk roll is generic over `trunkMin`/`trunkMax`.
  `tryGrowTree` rolls each type's density, then enforces ground-only
  guards: grass, above the waterline, river-bank margin, slope tolerance.
  New types register a spec; the placement loop is type-agnostic.

## Broad logic (mobs)

- Target debug (cheat only, `?cheat=1`): C aims a block (the first corner),
  holding C grows the selection into the box between that block and the cell
  under the cursor (the second corner — it follows the cursor in every
  direction, from any first aim), C released arms the target (the kind follows
  the shape of the box: one cell is a block, a flat box an area on that plane,
  a thicker one a volume), and C on a mob sends it there —
  the green overlay shows the selection as one translucent green box with
  its subtle edges, the planned path, and the mob. A
  target with no path is refused at once; an arrival clears the overlay; C while
  a mob walks cancels everything. The selection math and the transitions live in
  `targets-debug-state.js` (three-free, headless-tested); the overlay, the mob
  tint, and the input plumbing live in `targets-debug.js`.

- Targets and navigation: a mob target is a set of blocks (`src/mobs/targets.js`)
  and the goal is always "touch one of them" — the feet cell on top of a target
  block, or, when the mob cannot climb it, a lateral cell beside it (the goal
  tiers are tried in order, so a block flush with the ground is stood on and a
  block lying on the ground is approached from the side). A plan is a cell A*
  over the world's walkable feet cells
  (`src/mobs/nav.js`), gated by the mob capabilities through the
  traversal-strategy registry (`ground-walk` today; `jump`/`swim`/`fly` register
  their own strategy later). The planner chooses where; the existing movement
  primitives do the walking — open roam, wall-follow, 1-wide, and 2-wide all
  drive the planned commit, so no new locomotion code exists.
- The plan is the priority, the primitives are the means. The executor steers
  by pure pursuit: the mob is projected onto the planned line and aims at the
  point ahead on it, so its real trajectory stays on the planned path (the
  rigs hold it within the band — the mob's centre stays inside its planned
  cell).
  The primitives may take the local line — a wall-follow ride hugs the wall
  beside the path, the 1-wide servo runs the corridor, a 2-wide crossing
  threads the gap — but never off it: a rail that runs against the planned
  direction, or that drifts off the band around the planned cells, is dropped
  (at the contact latch, at the ride's exits and corner takes, at its budget
  away-quit, and as the last word before the lane drives), the corridor servo
  takes the planned exit instead of the axis the mob happens to face, and the
  mouth machinery draws only the mouths that lie on the plan.
- A mob on a plan owns its path: it is the top avoidance tier, so it holds its
  line and never yields, and every other mob reads it as a threat and gives
  way (slow, sidestep, detach, turn-away); the separation backstop never
  shoves it, the whole correction goes to the other mob. A blocked mob
  replans — around the mobs in its way (a moving mob counts exactly like a
  parked one) — until it arrives, and only a world without any path left ends
  the plan: the mob gives up. The blocked decision is taken on the route, not
  on the body: a mob that slides along a wall has not advanced on its path,
  so it decides within a fraction of a second and turns to the new route at
  once (the turn itself stays smooth). No path means no plan: the mob keeps
   walking free.
 - Mob vertical datum (normative): no probe and no action ever assumes a
   floor at y = 0. Bounded dims keep the y = 0 stop (the floor exists there);
   infinite dims (`dimInfinite`, the TNT sky) scan below it at bounded cost —
   `groundBelow` keeps its 8-deep cap without the `>= 0` bound, `hasSupport`
   scans `SUPPORT_SCAN = 8` under the feet (identical outcomes: the touch rule
   only reads the layer touching the feet, the nearest-solid break cannot
   differ), the Enderman spot probes (`spotSupportedDim`, `spotGroundY`) apply
   the same split. Everything above inherits it with no fork: `footingOk`,
   `makeStepOk`, `strideTarget`, `segmentWalkable`, `stepVertical`, the `nav.js`
   planner, grab-release landing (`carry.js`), and blast flight. In a
   floorless void there is nothing to stand on, so falling forever stays the
   design — not a bug. Headless-tested by
   `tests/headless/mobs/subzero.test.mjs`.

- Farm livestock share the directional free-roam mover and the strict 1-wide
  corridor servo. Lane classification and turn arcs stay body-probed to keep
  tight corners traversable; a straight, same-level dead-end seek additionally
  checks the forward nose circle and begins its U-turn before the head reaches

## Extension pattern

Seed rule (fundamental): every added feature must be controllable with the
`?seed=` world seed wherever possible. Worldgen and gameplay draws go
through `hash2`/`fbm(seed + salt)` or a seeded setter (`setFlowerSeed`,
`setGlowSeed`, `setMobSeed`, `setTntStreamSeed`); `main.js` pins one session
seed from `?seed=` (`rollSeed`) and reuses it for every generation while it
is present, rolling fresh otherwise. `Math.random`/`Date.now` in a tick or
generation path are forbidden except for the documented cosmetic exemptions:
particle bursts, precip drops, sky stars, canvas textures, help-diagram
shuffles, and per-frame death-shake jitter — ephemeral, never persisted.

Every variant family follows the same shape — new variants are registry
entries, never framework forks:

- One exported registry array of spec objects, each with a `key`
   (`TREE_TYPES`, `FLOWER_VARIANTS`, `GLOW_VARIANTS`, `TNT_TYPES`, `HOOK_TYPES`, `PRECIP_TYPES`, `HALO_SOURCES`, `REGIONS`, `DIMENSIONS`, `MOB_TYPES`, `LIVESTOCK_SPECS`, `TARGET_KINDS`, traversal strategies in `nav.js`).
- Shared properties live once in a module-local `*_DEFAULTS` object;
  entries spread it first and override only what differs.
- Differing numbers are entry properties; differing behavior is a
  capability flag the framework branches on (`pool`, `knockback`, `light`,
  `clearsLiquids`, `revealMaterials`, `pull`, `locomotion`) or an optional function prop (`carveBlast`,
  `spawnBlastFx`, `make/tick/clearLitVisual`, `grow`, `filter`, `contains`,
  `factor`, `onFade`, `tick`);
  kind strings (`key`, `blastKind`, `countdownKind`, `fxKind`) are stable
  identifiers, never branch conditions — dispatch goes through flags and
  hooks, or through a per-kind spec object looked up by key (e.g. camera
  shake via `shakeSpecFor(kind)`). Framework code never switches on kind
  names — new variants add entries (and any new flags/hooks they need),
  never forks.
- Spec keys are stable strings, never array indices, so a future save
  format survives reordering.
- Generic `spawnBurst` supports directional cones with `direction` and `spread`; dragon breath uses this emitter for its three-second particle jets.
- Every tick-shaped hook (`tickLitVisual`, `spawnBlastFx`, precip `active`/`landed`, `REGIONS` factor) obeys the Pause contract above: `dt` + sim-time in, no wall-clock out.
- Per-dimension properties follow the same shape at the dimension level:
  `DIMENSIONS` specs carry gameplay props (`moon`, `ultra`, `skyGrapple`,
  `infinite`, ...) read through `dim*` accessors, and render props ride the
  per-dim `env` (`sky`, `fog`, `sun`, `space`, ...). Framework code never
  branches on dimension keys — a new behavior asks "does this belong to a
  dimension?" and ships as a spec field or env key; a new dimension walks the
  checklist (env, moon?, ultra mode, hotbar, spawn, arrival, frameKeys, persistence, ambient,   fullView, renderDist, respawnY (null = no floor),
  floorY (`0`, `null` = floorless), region `dim` tags, precip `active`s, gravity zones).
- Cosmetic variants follow the recipe: weighted options table → stored per-block look drawn at placement (`flowerVariantAt`/`flowerAngleAt` reads, `noteFlowerPlace` draws; `glowVariantAt`, clustered on place) → baked geometries/materials + shared material.

Single-anatomy numbers stay plain constants: world dimensions, body
physics, render budgets. Single-spec systems (`TERRAIN`, `VILLAGE_SPEC`) become registries only when a second variant arrives.

## Nether portal-frame rules (normative)

Every tunnel mouth in the Nether carries a glowstone ring sized on its
carved opening (one centered pool lamp per ring via `netherRingLights` — rings
are portal structures, never chain-stride members), and every bore runs into
the central lava column. The siting
rules below are hard guarantees, not tuning — the generator constructs them
and the three-phase enforcement pass (re-clear bores/corridors, re-seal
shells, re-place rings last) re-asserts them per chunk:
- Uniform spread on the visible flank only: fan headings are stratified —
  one mouth per arc tenth over the facing hemisphere (`MOUTH_ARC` around the
  platform axis, `MOUTH_SEP` minimum separation, 10 distinct heights at or
  above `FAN_PLAT_MIN`); rear faces never host a frame. Three ground
  bridges per volcano are sited first on every volcano — before any fan
  anywhere, so exit tubes contend only with rock, lava and other bridges,
  never with the other volcano's long view corridors — one per arc sector
  (left, centre, right, `MOUTH_SEP` kept from the fan): each tip stands
    5..15 blocks clear of the flank   (`TIP_OVERHANG_MIN/MAX` on
    `tipD - radius`, whole visible run in 1-thick shell), either on a
    landing shelf grown jointly under the tip — flat shelf at `plat - 1`
    (`plat = NETHER_FIRE_LEVEL + 2..+4`), extending in front of the mouth;
    a failed shelf is rolled back, so orphans never clutter the sea — or
    right on flat island relief 0..10 above the sea (`spread ≤ 2`,
    `plat = shelfTop + 1`, the island doubles as the floor). No socle
    masonry anywhere — every mouth stands on rock. Outside the cone the
    walkway and corridor never touch island rock (`topAt ≤ plat - 1` over
    the whole bore+corridor footprint): low bridges route around fbm relief
    instead of carving it. Three bridges per volcano, guaranteed: sector
    slots (200 attempts each) then full-arc sweeps (2000 at half
    separation, 2000 at zero separation — the exact vetoes alone forbid any
    real overlap) and, only for still-empty slots, a carve fallback that
    lifts just the rock-touch veto (`t.carvedCorridor`, corridor rock sliced
    master-style; lava, pad, bands, frames and other tubes stay vetoed
    exactly as before) — strict re-site throughout, never clamped. Tips
    stay in their own volcano's half
    (Voronoi check) and clear of the central pad (`tubeHitsPad` ± 4), so the
    two volcanoes never crowd each other out; the fan still places its own
    ten around them.
    Bridges never cross each other
    outside the shared crater chamber (`MOUTH_SEP` + exact `tubesCross` +
    reservations; inside `craterR + 6` every envelope merges — the core is
    solid rock carved open identically, never void — so the chamber is a
    doorway, never a hole). A bridge touches only its own shelf islet
    if it has one (`tubeHitsDisc`), in both directions.
  - No cascade intersection: the ban mask (`buildCascadeMask`, bands plus 2
  cells) prefilters every lava veto and `courseClearance`/`boreBlocked`
  refuse any mouth whose walkway or ring touches a lava band, checked all
  the way from the crater edge to the mouth; the exact per-column span
  still decides where the mask is set, so a high walkway may thread over a
  low fall. Bands run from the crater lip down the cone, then drape over
  whatever island relief stands in the way until the lava sea (trench
  scanned while terrain stays above fire, cap foot+60), free from lip to
  water: no shelf (radius + 6), no bridge or fan envelope ever touches them.
  Tunnels never carry
  lava in the walkway, and the bore always reaches bare shaft lava with no
  rock wall left in between (floor lava capped to rock, so the walk stays dry
  and hole-free up to the lava face).
  - Big rugged fbm islands (master's two-scale noise recipe, capped at
  `FBM_TOP_MAX = FIRE+10`, one block below the lowest fan shell floor):
  `NETHER_LAND_OFFSET` (default 0 = current rendering) shifts the fbm base
  to tune the land share (~±10 ratio points per ∓2 around the ~1/3 default,
  useful range [-4, +4]; rivers stay absolute, the cap still bounds every
  island, siting vetoes unchanged — mean only, never per-seed variance).
  Rivers carve lava canyons through them, cliff streaks pour off their sea
  falls, lava bands drape over them — but no tunnel ever carves them. No
  island ever stands within 5 blocks of
  a lava band (`CASCADE_CLEAR` margin around each course over
  `[craterR, trenchEnd]`, hard carve like master's trenches — islands may
  stand anywhere beyond that, including between the two courses). Flat
  landing shelves for every bridge
  (`ISLET_TOP_MAX`, opened on the lava sea only, never on a cone, the pad,
  another shelf, a band (+ 6 margin) or a bridge envelope); low bridges
  route around island rock through the terrain veto. Fans sit a full band
  above every relief top (`FAN_PLAT_MIN`), so no fan envelope ever needs
  an island veto and corridors never slice an island.
- Ring sized on the carved mouth (`mouthCols`: integer columns with `d`
  within half a block of `dOut` and `f` in the band, 7–9 by heading):
  full-height jambs on the first/last columns, sill and lintel rows across
  (one deterministic hue per mouth, one rock sill cell under the ring when
  the ground dips). The frame glues flush to the wall face — never recessed,
  no niche — and always lands exactly on the opening edges, whatever the
  heading. A rock collar seals every face- and diagonal-neighbour of the
  ring that is not frame, walkway or corridor, within the mouth slice or
  behind it only (`frameCollarKeys`/`sealFrameCollar`, reserved like built
  rock, roof trim above the doorway like the shell's) — backing, never a
  lip in front — and a paved doorstep lowers the floor past the frame
  (`doorstepCells`/`sealDoorstep`, one below sill level over
  `dOut..dOut+1.5`, only air ever filled so the glowstone sill reads over
  it, reserved like built rock and known to
  the crossing test, never narrowing another tube's walkway or corridor), so no vertical slot
  and no doorstep pit survives between the glowstone jambs and the shell on
  any heading — the doorway front stays open by construction.
- Hermetic tube, no holes: every bore is carved open, then wrapped in a
  1-block lining hugging the walkway (floor `plat`, roof `plat+7`, one
  column per side — the rock reveal directly behind the frame ring), plus a
   second layer where buried — floor `plat-1`, roof `plat+8`, outer columns
   `f in {-2,9}` — but only at or below the natural surface (`y <= topAt`),
   or where rock stands within one cell sideways (1-block pillars closing
   the slot between lining and hillside): never a rock cap over the doorway
   or wings in open air, the volcano keeps its no-tunnel look, and no gap
   is ever left between rock and tunnel. Interior and shell are one partition of a single
  analytic band (`d` along the heading, `f = lateral + 4`; interior
  `0 <= f < 8`, buried shell `f in [-2,10)`, exposed shell `f in [-1,9)`,
  minus interior): a cell is one or the other, never both, never neither —
  no gap on any heading, no rock inside the walkway. The shell only ever
  fills air or lava outside the shaft, never touching another tube's
  interior (`tubeInteriorAt`), corridor, a frame (`ringCells`), the pad, or
the shaft column. The only openings are the frame doorway and the lava
face (dry sill, flat on cardinal headings, regular crenellation on
diagonals). `finishTunnel` derives `thinFrom` for every tunnel (backed up from
  the mouth while no rock rises above the floor), so fan and bridges alike
  wear 1 block in the open and 2 in rock.
- Full visibility of every block from the front: the full-width gallery bore
  (6 high, 8 wide from the mouth to the lava, no narrowing, no inner pillars —
   shell walls sit outside the doorway profile) plus the view corridor (10
     wide to the exit with the sill sight row at `y = plat` from the frame
  plane (disjoint by level from the lowered doorstep below), then the
  `plat+1..plat+7` band until open sky holds `APRON_OPEN` columns, capped at
  `APRON_CAP`) is cleared of rock — so zero stone stands in front of any
  glowstone block or inside the walk profile, by construction, at every
  mouth on every heading. The exit itself is two-tier: a
  fully open row within `EXIT_CAP`, else a shallow notch (overburden within
  `EXIT_NOTCH`) within `EXIT_FAR`, cleared the same way as a rock canyon. No
  lattice rounding anywhere in siting or construction: `boreBlocked`,
  `tubesCross` and every build pass decide per cell through the shared
  classifiers (`tubeInteriorAt`/`tubeCorridorAt`/`tubeShellAt`), and shells
  yield to any tube's airspace (`clearOf`), so a new mouth never punches a
  hole in an accepted tube and crossings are refused outright — except
  inside the shared crater chamber (`craterR + 6`), where every envelope
  merges by construction. Lava and glowstone are never touched, the pad is
  cleared through so a low corridor is never blocked. The walkway lava veto
  is exact per column (`boreBlocked` over the whole crater-to-mouth run,
  both volcanoes' bands included) — no lateral pre-gate, so a high walkway
  may honestly thread over a low fall.
- No stone pillar in or before any tunnel: the build carves the bore, seals
  the shell, places the ring, clears the corridor; the shell never fills a
  walkway cell.

## Extension points (dimensions and blocks)

- Dimensions are first-class: `DIMENSIONS` in `world/dimensions.js` is the registry (generator, sync + async, env preset, spawn, `arrival` portal-return policy, `frameKeys` worldgen frame index, `persistence`, respawnY floor (null = none), floor level (`floorY`: `0`, `null` = floorless), `infinite` streaming, `ambient`, `fullView`, moon/ultra/skyGrapple/tntTiersUnlocked props); `store.js` maps derive from `DIMENSION_KEYS` and a dimension may `registerRenderDist`, portals keep per-dim frame sets, and the main loop switches through `runTravel`. New dimensions register a spec beside the relevant world generator — no framework forks. Every dimension key is a valid `?startdim=<key>` boot target (`?startdim=nether` boots the Nether revealed: `fullView` skips the unload-horizon fog cap and the boot reveal, while the missing-chunk guard still hides unbuilt geometry). When a user requests a new dimension, ask them which URL key to use before implementation, then document and use it consistently. Infinite dims stream voxels through a `tntstream.js`-shaped lattice (deterministic cells, budgeted gen/evict, pinned player content); blasts in infinite dims clamp to the key range and ultras wipe per the dimension's ultra mode (bands in the overworld, ignition window elsewhere), never the whole level.
- Block ids append-only; dimension-specific blocks slot into BLOCK_INFO.
- The hotbar list is dynamic (add/remove/change); band or dimension swaps go in `hotbar.js` callers, and per-dimension lists come from `dimHotbar` (locked TNT tiers filtered there, never in the render). The End profile maps water to Moon Water and flower to Glowstone; the Nether maps water to Lava and flower to Glowstone. New tier families add their threshold to `tntunlock.js`.
- End portals enter the End from any dimension; inside the End they return to the Overworld. The generated return frame is protected, but its fill is disabled until dragon victory; every End re-entry regenerates the platform and return frame, respawns the dragon, and disables the return fill again.
- A distant body or occluded structure sharing a dimension's sky is a `REGIONS` entry (`contains` + `factor` + optional `onFade`), never a mesher fork.
